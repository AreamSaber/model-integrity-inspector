# ADR-0006: Append-only and tamper-evident audit log

Status: Accepted  
Date: 2026-09-04

## Context

PRD V1.0 要求敏感操作进入不可篡改审计日志。仅把事件写入普通业务表不能满足该要求：普通应用写路径可能误更新或删除记录，数据库离线修改也无法被发现。同时 V1.0 不允许把外部 WORM、S3 或日志平台变成默认依赖。

## Decision

- 将产品中的“不可篡改”落实为：应用权限下只追加、普通用户不可删除、数据库离线篡改可检测；不声称抵御同时控制数据库、应用制品和外置完整性密钥的主机超级管理员。
- `integrity_audit_logs` 只提供 `Append` 和 `Verify` Repository 能力，不提供更新接口。敏感状态变更与对应审计事件在同一数据库事务提交；强制审计写入失败时，敏感变更失败关闭。
- 每个组织维护 `integrity_audit_chain_heads`。每条事件包含不可变 event id、组织、时间、主体、动作、对象、结果、脱敏差异、前序哈希、事件哈希和完整性密钥版本。
- `event_hash = HMAC-SHA-256(audit_integrity_key, canonical_event || prev_hash)`。规范化格式和字段顺序版本化；完整性密钥与 Secret wrapping/fingerprint 密钥用途分离并位于业务数据库之外。
- PostgreSQL 追加时锁定对应组织链头；SQLite 使用短单写事务，保证同一组织链严格有序。系统提供按组织/时间范围验证以及恢复后的全链验证。
- 默认保留 365 天。清理只能处理已密封分段，并永久保留分段起止哈希、事件数量、时间范围、规范化版本、密钥版本和删除事件；清理权限与普通应用写权限分离。
- 应用数据库角色只授予审计表 `INSERT/SELECT`；清理使用独立维护角色。SQLite 无数据库角色能力，因此依靠 Repository 隔离、文件权限和 HMAC 链检测篡改。

## Consequences

- 每次审计追加需要一次组织链头串行化操作；链按组织拆分，避免全局热点。
- HMAC 链能够检测事件修改、插入、重排和未按密封规则删除，但不能阻止拥有数据库与外置完整性密钥的联合特权主体伪造历史。
- 密钥轮换后旧完整性密钥必须按保留期可用于验证；只允许新事件使用当前版本。
- 健康检查执行轻量尾链验证，完整验证由运维命令、备份恢复和发布演练执行。

## Alternatives rejected

- 普通可更新数据库表：不能兑现不可篡改要求，也无法检测离线修改。
- 单一全局哈希链：并发组织共享一个写热点，降低生产吞吐和隔离性。
- 强制外部 WORM/S3/SIEM：违反无外部依赖的 V1.0 独立部署边界。
- 仅依赖数据库触发器：对数据库超级用户和离线修改不可检测，也难以保持 SQLite/PostgreSQL 等价行为。

## Failure, rollback, security and data

强制审计事件无法追加时，密钥、权限、规则、基线、导出、复核和删除等敏感变更不得提交。链验证失败时 readiness 暴露分类状态并触发高优先级告警，但接口不得返回事件正文、密钥路径或 HMAC 值。应用回滚不得回写或删除审计事件；数据库恢复后必须先验证链与密封分段 manifest，再恢复敏感写操作。
