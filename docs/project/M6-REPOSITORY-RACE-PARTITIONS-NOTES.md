# M6 集成：仓储 race 进程累计预算分片

2026-09-10。只调整测试调度，不更改产品期限、测试断言、算法阈值、工作流 matrix、
required gate 或分支保护；不是 M7 性能/容量验收。

## 真实失败依据

CI `34439268496` / commit `976560519010fd8f837b558936636511a5d4367a` 的
`repository-race-2`（job `102750699748`）实际失败。原始日志明确显示：

- 原选择为全仓储 450 个父级中的 75 个，精确覆盖验证已通过。
- `panic: test timed out after 10m0s`，包总耗时 `600.044s`。
- 被终止时 `TestSystemStatusCorruptionAndActiveJobBounds/sqlite` 才运行 7 秒。

这是整组进程累计预算耗尽的证据，不是某个用例执行了十分钟，也没有据此认定
data race 或锁死；该用例的高人口边界和其他断言全部保留。原 CI 失败不追认通过。
首次下载日志的观察失败不代表任务重启/终止；重读的是同一个已失败 job。

## 修订及覆盖合同

保留六个独立仓储 CI job。每个 job 先真实 `go test -race -list` 枚举全部
Test/Example/Fuzz 父级，按原 ordinal 六分组；再把本组按 ordinal 分成两个
顺序执行的子组。只有一个父级时只生成一个非空子组。Worker 仍为原六组各一个进程。

每个实际测试进程仍使用 `-race -count=1 -timeout=10m` 和精确父级锚定 `-run`；
没有 `-skip`、driver 子路径过滤、默认 fuzz seed 遗漏、重试或失败后继续。
父级下的所有嵌套子测试原样执行；每一层都用精确集合和正则验证无遗漏、无重复。
不改变原 25 分钟仓储 job 上限；若新的实际 CI 仍超预算，必须继续按真实日志处理。

`-NativeGo` 的验证也改为检查真实执行子组，而非只验证不再实际执行的外层选择。
独立 PostgreSQL identity/API、Core、Other 和所有 Worker 调用覆盖保持不变。
