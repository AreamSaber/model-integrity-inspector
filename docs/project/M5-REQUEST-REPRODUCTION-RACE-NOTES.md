## Which deadline expired

The failing line is the first call to `PrepareRequestReproduction` on a real
adapter-built request containing 900 KiB of `x`, before its canonical decoder
check and before the separate 110,000-repeat redaction-expansion case.

The caller is `context.Background()`. `prepareContext` introduces the unchanged
two-second deadline at the start of the pure Prepare operation. That lifetime
covers source validation, real-wire reconstruction and comparison, credential
dictionary construction, text redaction and suspicious-credential checks,
canonical encoding, and final known-credential collision scanning. It excludes
the fixture's initial source construction, sealing, opening, HTTP, Worker
execution, lease management and published report analysis.

The relevant `ErrCancelled` paths require the derived context to be done.
There is no external cancellation in this fixture, so the internal Prepare
deadline expired. The remote log does not contain a CPU profile or phase timing;
it does not identify a unique cause for exceeding that budget.

## Local profiling and safe optimization

The unmodified Windows non-race large-request test passed three rounds at
0.12–0.13 seconds per test. This is not a native Linux race reproduction.
An unmodified 15-round CPU profile collected 2.17 seconds of CPU samples:

- `suspect`: 1.00 second cumulative, 46.08% of total.
- Its assignment regex `FindAllStringSubmatch`: 820 milliseconds cumulative.
- Its case-sensitive token regex: 180 milliseconds cumulative.

The profile files are generated, test-only temporary artifacts under
`C:/Users/Camellic/AppData/Local/Temp/mii-request-profile-062902384277483c92e34bc443bfb7ac`.
They do not contain user request bodies or real keys. They were generated by
the existing 900 KiB/expansion test, without a database or network call.

The only production edit is a necessary-condition optimization in shared
`evidencedisplay/redact.go`, explicitly authorized after that profile:

1. PEM detection retains the exact original `strings.ToLower` substring rule.
2. Case-sensitive token detection first looks for exact `sk-`, `ghp_` or `AKIA`
   prefixes. If present, the unchanged original regex still decides suffix
   lengths, character classes and word boundaries.
3. Assignment detection falls back to the unchanged original Unicode-folding
   regex for **every non-ASCII input**. No approximate Unicode normalization is
   introduced. For ASCII input, the nine literal lowercase forms corresponding
   to the original alternative/optional-separator grammar are necessary
   substrings. A candidate still runs the original regex and original allowed
   redacted-value checks. Substring lookup deliberately has no word boundary,
   matching the original assignment rule's semantics.

False-positive candidates only cost a regex call; candidates cannot themselves
make a disclosure decision. The two original regex expressions, input limits,
two-second budget, expansion rules and final collision checks are unchanged.
`request_reproduction.go` did not need a separate implementation or policy fork.

Same-machine non-race measurements (`-benchtime=300ms -count=3`):

| Operation | Before | After |
| --- | --- | --- |
| Real 900 KiB Prepare | 86.2 / 89.5 / 92.5 ms | 20.8 / 20.0 / 19.6 ms |
| Suspicious-credential scan | 67–69 ms | 1.16–1.20 ms |

The measured preparation improvement is approximately 4.5 times for this input.
No timing assertion or larger allowed duration was added. Non-ASCII or candidate-
containing text may still need the complete regex, and there is no guarantee
that every permitted input completes within two seconds under arbitrary load.
The profile supports removing this avoidable cost, not a claim that it was the
sole cause of the remote failure.

## Validation and remaining evidence

New `request_reproduction_performance_test.go` retains a frozen pre-optimization
policy oracle and checks that both original regex strings are unchanged. Its
tests cover PEM behavior, token case/length/word boundaries, assignment matching
inside longer words, permitted redaction markers, separators, every SimpleFold
alternative of each ASCII letter in the assignment names (including long s and
Kelvin sign), a deterministic mixed-language differential corpus, and all valid
non-ASCII Unicode scalar values taking the conservative fallback. It checks the
assignment prefilter independently even when an allowed marker would make the
overall policy return false. A separate fuzz target compares against the same
original policy; the original 900 KiB and expansion test remains unchanged.

Actual local Windows results after the final code changes:

- `go test ./internal/integrity/evidencedisplay -count=3`: PASS, 1.115 seconds.
- Single-worker differential fuzzing for three seconds: PASS, 34,792 executions,
  67 new interesting inputs; total command duration 4.407 seconds.

  -count=3`: PASS, 0.109 seconds.
- `go test ./tests/contracts -run '^TestEvidenceDisplay' -count=3`: PASS,
  0.191 seconds.
- `golangci-lint run ./internal/integrity/evidencedisplay`: 0 issues.

The parent then independently reviewed the complete production/test diff and
reported whole-package three-round results: `evidencedisplay` PASS in 1.157
seconds and `secret` PASS in 0.465 seconds, plus lint on both packages with
0 issues. These are local non-race validation of the optimization. The parent's

The local Go environment has `CGO_ENABLED=0`, no discovered gcc/clang compiler,
and no usable WSL Linux distribution. No native Linux or Windows race execution
