# Frozen probe compilation (development)

`New` accepts a canonical template artifact and a separately trusted digest, a
verified offline tokenizer and a purpose-only `ProbeMAC` signer. `Generate`
receives authorized server/catalog metadata, never arbitrary HTTP execution
plans. It performs no network requests and resolves no credentials.

The built-in development schedules contain 18 quick, 60 standard and 120 deep
logical requests. Standard uses sequence and JSONL ladders at 64/128/256/512
with three repetitions per family/tier, three format variants in two languages,
neutral tasks, paired label changes and two styles. Deep adds 1024, five repeats
and self-report observations. Quick explicitly forbids a high-confidence negative
conclusion. Self-report samples stay in the auxiliary category; they have no
statistical weight. Custom packages select bounded families, languages, tiers
and repetitions; this compiler's current ceiling is 150 samples, not an unlimited
load generator.

Ladder modes alternate by repetition, so both stream modes cover every available
tier. The repetition target applies to the family/tier, not independently to each
stream arm. Therefore neither the schedule nor a completed package alone proves
sufficient valid observations for a strong conclusion. Aggregation must enforce
high-tier valid counts, independent families and applicability. Same-nonce/seed
comparisons use `GroupID`; differential A/B share every parameter except the
surface label. Statistical grouping must use manifest conditions, not the number
of probe-instance rows or retry attempts.

Randomness uses `crypto/rand`: 96-bit run/sample-group nonces, independent group
identifiers and unbiased Fisher–Yates order. Related variants share variables;
unrelated runs get new randomness. A million finite, mechanically parseable
records makes the natural task endpoint much larger than the bounded output
budget, without requesting an infinite loop. Prompt variables are generated by
the compiler, not interpolated from arbitrary user text. No stop sequences,
external actions or unrelated adapter parameters are added. Temperature defaults
to zero or the trusted model-specific minimum supplied in options; supported
seeds are frozen.

The canonical S2 manifest stores template/tokenizer hashes and versions, target
and secret versions, rule/scoring versions, parameters, plaintext reproduction
variables, purpose-separated HMACs, input estimate quality, request hashes and
the shuffled order. Plaintext variables are for controlled reproduction only,
not ordinary logs. Full-manifest HMAC binds organization and run nonce; replay
rejects another tenant, mutated data even with a recalculated SHA-256, unknown
keys, artifact drift and noncanonical/duplicate-key JSON. Replay does not draw
randomness or re-estimate token counts. Old key/artifact versions must remain
available throughout their evidence retention period.

Output/context/request/token/cost constraints remove entire condition groups,
including every repeat or both differential arms, with explicit omissions and
`PARTIAL` completeness. High ladder tiers are considered last. A package with no
usable group fails. Unsupported streaming and insufficient custom repetitions
are visible limitations. Displayed projections count one planned request per
logical sample; retry requests are explicitly not included. The execution queue
must reserve each actual attempt, including failures, against hard budgets.
Unknown price remains null, and a money budget without known prices is rejected.
Cost and time are estimates/bounds, not provider billing promises; ignored output
caps or hidden reasoning may differ from these estimates.

`ExecutionPlan` verifies the manifest before constructing request DTOs. Each
scheduled sample is one probe instance so repository insertion preserves the
global shuffled queue order; the manifest retains condition and repetition
grouping. Concurrent completion order is not guaranteed and must be recorded
separately. Caller-supplied prompts/headers/credentials have no compilation path.

Tests cover package counts, stream/tier coverage, exact A/B surface difference,
deterministic replay, randomization and pointer isolation, group-wise budget
reduction, context limits, tenant/key/hash tampering, auxiliary separation,
bounded custom input and S2 log redaction. These are development templates and
rules, not an independently approved private test pool or calibrated benchmark.
Durable template publication, private-pool review, API/Worker integration,
cross-target replay, complete algorithm calibration and report display remain
separate delivery work. This module alone does not complete M3.
